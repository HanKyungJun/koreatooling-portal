# Apps Script 콘솔 작업 런북 (2026-09-22)

> 담당: **한경준님만 가능** — 실제 코드는 Apps Script 콘솔에 있고 저장소의 `.gs` 는 사본이다.
> 소요: 두 건 합쳐 **약 20~30분** [추정값].

## 🔴 시작 전에 — 프로젝트가 **두 개**다. 섞지 말 것

| | A. 공개 폼 | B. 현장기록 |
|---|---|---|
| 스크립트 | `netlify_to_sheets.gs` | `scripts/field_record_gas.v2.gs` |
| 쓰는 곳 | `portal.js` 의 `GAS_FORM_URL` | `.env` 의 `FIELD_RECORD_GAS_URL` |
| 🔴 **해야 할 배포 동작** | **「새 버전」 — URL 유지** | **「새 배포」 — URL 변경** |
| 이유 | URL 바뀌면 `portal.js` 도 고쳐야 함 | **옛 URL 을 죽이는 것이 목적** |

**두 프로젝트가 같은 스프레드시트(`코리아툴링 폼 접수 관리`)를 씁니다.** 배포 동작이 정반대이므로, 한 콘솔에서 연달아 하다 바꿔 누르기 쉽다. **A 를 끝내고 확인한 뒤 B 로 넘어간다.**

## A. 공개 폼 — 견적문의 탭 + 스크립트 갱신

### A-0. 🔴 현재 상태 (2026-09-22 실측)

| 확인 | 결과 |
|---|---|
| `견적문의` 탭 | 🔴 **없음** — 탭 4개뿐(재연마의뢰·불량신고·진행문의·소모품요청) |
| 스프레드시트 최종 수정 | **2026-04-27** — 그 이후 **어느 탭에도 기록이 없다** |
| 유일한 데이터 행 | 재연마의뢰 탭의 2026-04-27 테스트 행 1건(`ㅁㄴㅇ`) |

⚠️ **「기록이 없다」는 두 가지로 읽힙니다** — ①제출 자체가 없었다 ②제출이 실패했다. **어느 쪽인지 확인하지 못했습니다** [추정값]. 포털을 거래처에 아직 안 알렸다면 ①이 자연스럽습니다.

### A-1. 🔴 지금 estimate.html 은 조용히 실패한다 [실측 검증 — 소스 판독]

`netlify_to_sheets.gs` 27~28행:

```js
var sheet = ss.getSheetByName(sheetName);
if (!sheet) return ContentService.createTextOutput('sheet not found: ' + sheetName);
```

- **탭이 없으면 `appendRow` 도 `sendEmail` 도 도달하지 않습니다** — 시트 기록 없음 + **알림 메일도 없음**
- 콘솔에 아직 옛 버전이 올라가 있다면 `estimate-form` 이 `sheetMap` 에 없어 `unknown form` 으로 끝납니다 — **어느 쪽이든 실패**
- 클라이언트는 iframe POST 라 응답 본문을 못 읽습니다 → **화면에는 성공으로 보입니다**

⇒ **고객이 견적 문의를 넣어도 아무도 모릅니다.**

### A-2. 견적문의 탭 생성

스프레드시트 **`코리아툴링 폼 접수 관리`** 에 **`견적문의`** 탭을 만들고 1행에 아래를 넣습니다(탭 이름 정확히 일치해야 함 — `sheetMap` 이 이 이름으로 찾습니다).

```
시간	회사명	담당자	연락처	이메일	구분	재질	규격	수량	희망납기	월예상수량	참고사항	첨부파일
```

> 위 줄은 탭 구분입니다. A1 에 붙여넣으면 13칸으로 나뉩니다.

### A-3. 스크립트 갱신 — 「새 버전」 (URL 유지)

1. Apps Script 콘솔에서 **공개 폼 프로젝트**를 엽니다
2. 저장소 루트 `netlify_to_sheets.gs` 내용을 **전체 복사해 덮어쓰기** → 저장
3. **배포 관리 → (기존 배포) 편집 → 버전: 새 버전 → 배포**
   - 🔴 **「새 배포」를 누르지 마세요.** URL 이 바뀌어 `portal.js` 수정이 따라옵니다

### A-4. 검증 — 여기까지 해야 끝난 것이다

포털 견적 문의 폼으로 **테스트 1건 제출** 후:

- [ ] `견적문의` 탭에 행이 생겼는가
- [ ] `hzn2001@toolkorea.co.kr` 로 `[KoreaTooling] Estimate Inquiry (…)` 메일이 왔는가

🔴 **화면의 「접수되었습니다」는 증거가 아닙니다** — 실패해도 똑같이 뜹니다. **시트와 메일 둘 다** 확인하세요.

⚠️ 테스트 행은 확인 후 지우시면 됩니다.

## B. 현장기록 GAS — 새 배포로 옛 URL 폐기

### B-0. 왜 급한가

배포 URL 이 `internal/field-record.js` 로 **공개 저장소 이력에 남아 있습니다.** 파일에서 지워도 **히스토리의 URL 은 계속 유효**합니다 — Gmail 앱 비밀번호와 같은 논리입니다(2026-09-02 (8) ①).

- 🟢 **읽기 유출은 없습니다** — `doGet` 은 `{status:'ok'}` 만 반환(2026-09-08 소스 판독)
- 🔴 **남는 위험은 쓰기 오염 + `notifyEmail()` 스팸** — 누구나 현장기록 시트에 쓸 수 있습니다
- 🔴 **URL 만 바꾸면 또 새면 같은 문제** → **토큰 검증을 같이 넣습니다**

### B-1. 순서 (이 순서대로)

1. **현장기록 프로젝트**에 `scripts/field_record_gas.v2.gs` 내용 붙여넣기 → 저장
2. **프로젝트 설정 → 스크립트 속성** 에 추가
   - 속성 이름: `SHARED_TOKEN`
   - 값: `.env` 의 `FIELD_RECORD_TOKEN` 과 **같은 값**
3. **배포 → 새 배포 → 웹 앱** (실행: 나 / 액세스: 모든 사용자) → **새 URL 복사**
4. `.env` 의 `FIELD_RECORD_GAS_URL` 을 새 URL 로 교체
   - 🔴 **PowerShell `Add-Content`·메모장 금지** — CP949 로 저장돼 한글 주석이 깨집니다. **VS Code** 로 여세요
5. `python generate.py` 실행 → 로그에 `→ 현장기록 설정 생성: internal/field-record-config.js` 확인
6. 🔴 **배포 관리 → 기존(옛) 배포 → 아카이브** — **여기까지 해야 옛 URL 이 죽습니다**

### B-2. 왜 순서가 어긋나도 화면은 안 죽는가

양쪽이 조건부 폴백이라 그렇습니다 — GAS 는 스크립트 속성이 없으면 검증을 건너뛰고, 클라이언트는 설정이 없으면 옛 URL 로 폴백합니다.

🔴 **그래서 중간 상태가 위험합니다.** 현장기록 제출이 실패해도 `submitData` 가 `catch` 에서 로컬 저장만 하고 **성공으로 표시**합니다. **한 번에 6단계를 끝내세요.**

### B-3. 검증

- [ ] 현장기록 폼에서 테스트 1건 → 시트에 행이 생기는가
- [ ] 옛 URL 로 POST 시 더 이상 쓰이지 않는가 (아카이브 확인)
