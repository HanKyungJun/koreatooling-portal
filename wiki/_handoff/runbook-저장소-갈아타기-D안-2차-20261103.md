# 공개 저장소 노출 정리 — 실행 절차 (2026-11-03, D안 2차)

> 결정: decisions.md **2026-11-03** · 1차 절차(상세 · 함정 설명): [[_handoff/runbook-저장소-갈아타기-D안]]
> 모든 git 명령은 **PowerShell** 에서 한경준님이 실행합니다(Cowork bash 에서는 git 쓰기 금지).
> 아래 명령 상자는 **그대로 붙여 넣어 실행**하는 용도라 주석을 넣지 않았습니다. 설명은 상자 밖에 있습니다.

## 0. 무엇을 하는가

| 단계 | 내용 | 효과 | 소요 |
|---|---|---|---|
| 1단계 (오늘) | 익명화 · ERP 파일 추적 제외를 커밋 · push | **지금 공개 화면**에서 거래처 실명 · ERP 주소가 빠짐 | 5분 |
| 2단계 (다른 날 오전) | 저장소 갈아타기(D안 2차) | **git 이력**에 남은 실명 · ERP 주소까지 비공개로 격리 | 1시간 |

1단계만 하면 최신 파일은 깨끗하지만, 저장소의 「커밋 기록」을 열면 09-01 ~ 11-03 사이 실명판을 볼 수 있습니다. 그래서 2단계가 필요합니다.

## 1단계 — 오늘 (5분)

### 1-1. 추적 제외 · 실명 검사 · 커밋

실행 위치는 일반 PowerShell 이면 됩니다.

```powershell
cd C:\Users\TOOLKOREA\Desktop\cnc-wiki
git rm --cached erp/dist/TricoERP.exe erp/dist/config.json erp/trico_client.py erp/probe_trico_service.py erp/probe_code_master.py erp/probe_workset_as.py erp/check_so.py erp/probe_dlv_mismatch.py
python scripts\anonymize_public.py --check
```

- `git rm --cached` 는 **저장소 추적만 끊습니다** — PC 의 파일은 그대로 있고, ERP 조회 · 일일보고는 그대로 돕니다.
- 마지막 줄이 **「거래처 실명 남은 파일: 0개」** 여야 다음으로 갑니다. 1개 이상이면 멈추고 그 목록을 Cowork 에 보여 주세요.

```powershell
git add -A
git status --short
```

- 목록 확인: `D  erp/...` 8줄(추적 제외) · `M` 39줄 안팎 · `A  scripts/anonymize_public.py`. **`wiki/_private/` 가 보이면 멈춤.**

```powershell
git commit -F outputs\commit_msg_20261103.txt
git push
git log --oneline origin/main..HEAD
```

- 마지막 명령 결과가 **빈 줄**이면 push 완료입니다.

## 2단계 — D안 2차 (평일 오전, 16:00 배치 전, 약 1시간)

1차 절차와 같습니다. **다른 점만** 표로 적고, 명령은 전부 다시 적었습니다.

| 항목 | 1차(09-01) | 2차(이번) |
|---|---|---|
| 옛 저장소 새 이름 | `koreatooling-portal-archive` | **`koreatooling-portal-archive2`** (앞 이름은 이미 사용 중) |
| 로컬 `.git` 보관 위치 | `..\cnc-wiki-git-archive-backup` | **`..\cnc-wiki-git-archive2-backup`** |
| 미러 백업 | `koreatooling-portal-backup.git` | **`koreatooling-portal-backup-20261103.git`** |
| 새 저장소 파일 수 | 481 | **720 ~ 740 예상** (11-03 추적 732 − 8) |
| 사라지는 커밋 SHA | 09-01 이전 | **09-01 ~ 11-03 (321개)** — archive2 에 남음 |

### 2-1. 준비

```powershell
cd C:\Users\TOOLKOREA\Desktop
git clone --mirror https://github.com/HanKyungJun/koreatooling-portal.git koreatooling-portal-backup-20261103.git
cd C:\Users\TOOLKOREA\Desktop\cnc-wiki
git status --short
git log --oneline origin/main..HEAD
git worktree list
```

- `git status --short` · 미푸시 둘 다 **빈 줄**이어야 합니다. `git worktree list` 는 1줄(본 폴더)만 나와야 합니다.

아래는 **관리자 권한 PowerShell** 에서 실행합니다(시작 메뉴 → PowerShell 우클릭 → 관리자 권한으로 실행).

```powershell
Get-ScheduledTask | Where-Object { $_.TaskName -like "*CNC*" } | Disable-ScheduledTask
Get-ScheduledTask | Where-Object { $_.TaskName -like "*CNC*" } | Select-Object TaskName, State
```

- State 가 전부 **Disabled** 인지 확인합니다.

### 2-2. GitHub 웹에서 (순서대로)

1. `koreatooling-portal` → Settings → Pages → Source: **None**
2. Settings → General → Repository name → **`koreatooling-portal-archive2`** → Rename
3. Settings → General → Danger Zone → Change visibility → **Make private**
4. 시크릿 창에서 `github.com/HanKyungJun/koreatooling-portal-archive2` → **404** 확인
5. New repository → 이름 **`koreatooling-portal`** · **Public** · README · .gitignore · license **모두 해제** → Create
   - 이름이 거부되면 **여기서 멈추고** Cowork 에 알려 주세요(1차 절차 ④ 대안 참고).

### 2-3. 로컬 이력 갈아끼우기 (일반 PowerShell)

```powershell
cd C:\Users\TOOLKOREA\Desktop\cnc-wiki
Move-Item .git ..\cnc-wiki-git-archive2-backup
Test-Path ..\cnc-wiki-git-archive2-backup
Test-Path .\.git
```

- 결과가 **True · False** 순서여야 합니다.

```powershell
git init
git branch -M main
git config user.name "HanKyungJun"
git config user.email "hankyungjun@koreatooling.com"
git config core.quotepath false
git add -A
(git status --short | Measure-Object -Line).Lines
```

- 숫자가 **720 ~ 740** 이면 정상. **2,000 을 넘으면 즉시 멈춤**(백업 폴더 · raw 유입).

```powershell
git status --short | Select-String -Pattern "raw/|_private|archive2-backup|worktrees|__pycache__|TricoERP|trico_client|erp/snapshot|\.env$"
python scripts\anonymize_public.py --check
```

- 첫 명령은 **아무것도 안 나와야** 정상, 두 번째는 **「거래처 실명 남은 파일: 0개」**.

```powershell
git commit -m "init: portal repo reset (D-plan 2nd) - history in koreatooling-portal-archive2"
git remote add origin https://github.com/HanKyungJun/koreatooling-portal.git
git push -u origin main
```

### 2-4. 토큰 · Pages · 자동화

1. GitHub → Settings → Developer settings → Fine-grained tokens → (자동 push 토큰) → Repository access 에 **새 `koreatooling-portal` 추가** · Contents: Read and write → Update
   - 이걸 빼먹으면 16:00 자동 push 가 403 으로 실패합니다(1차 ⑥-1 실측).
2. 새 저장소 → Settings → Pages → Deploy from a branch → `main` / `(root)` → Save

관리자 권한 PowerShell:

```powershell
Get-ScheduledTask | Where-Object { $_.TaskName -like "*CNC*" } | Enable-ScheduledTask
```

일반 PowerShell:

```powershell
cd C:\Users\TOOLKOREA\Desktop\cnc-wiki
python generate.py
git prune --expire=now
git count-objects -vH
```

- `wiki/reports/daily/generate.log` 에서 `push code=0` 확인(「업로드 완료」 문구만 보고 판단하지 않음).

## 3. 되돌리기

| 멈춘 곳 | 방법 |
|---|---|
| 2-2 중간 | archive2 를 원래 이름으로 Rename → Public → Pages 다시 켜기 |
| 2-3 이후 | `Remove-Item .git -Recurse -Force` 다음 `Move-Item ..\cnc-wiki-git-archive2-backup .git` → 위와 같음 |
| 최악 | `koreatooling-portal-backup-20261103.git` 에서 다시 받기 |

정상 동작 1 ~ 2주 확인 전에는 `cnc-wiki-git-archive2-backup` · 미러 백업을 지우지 않습니다.

## 4. 앞으로 (재발 방지)

- 공개 폴더에 거래처 자료를 둘 때: `python scripts\anonymize_public.py --apply 파일` (실명판은 `wiki/_private/` 로 복사됨)
- 커밋 전 점검: `python scripts\anonymize_public.py --check` → 0개
- 출하현황 · 표준공수 DB 를 다시 만드는 스크립트(`make_excel` · `make_excel_history` · `build_costdb`)는 저장 뒤 자동으로 익명화합니다. 사내 현황판(`generate.py`)은 실명판을 읽습니다.
- 실명 ↔ 코드 대조표: `wiki/_private/거래처_익명코드표.csv`(새 거래처는 ERP 저장본에서 자동으로 뒤에 붙음 · 한 번 정한 코드는 바꾸지 않음)
- ⚠️ 효과를 과대평가하지 않는다 — 09-01 ~ 11-03 동안 공개돼 있었고 **실제 열람 여부는 확인할 수 없다**. 이 작업은 「앞으로 발견될 가능성」을 줄이는 것이다.
