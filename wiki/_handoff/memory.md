# 프로젝트 메모리 (cnc-wiki)

> Codex/Claude/Cowork가 다음 작업에서 참고할 장기 메모입니다.
> 사용자의 선호, 프로젝트 운영 방식, 반복적으로 기억해야 할 사실을 짧게 누적합니다.

## 사용자/협업 방식

- 사용자는 전문 개발자는 아니지만, 현장 지식과 실제 데이터를 바탕으로 AI와 함께 정리·자동화·개선하는 방식을 선호한다.
- 답변은 한국어가 기본이며, 너무 복잡한 개발 용어보다 실제 작업 순서와 이유를 쉽게 설명하는 것이 좋다.
- Claude와 Codex를 병행해 사용할 수 있다. Claude는 문서/기획/긴 맥락 정리에, Codex는 코드 점검/자동화/보안 정리/파일 작업에 강점을 두는 식으로 협업하면 좋다.
- 기능 개선과 보안 정리는 섞지 않는 편을 선호한다. 보안 이슈는 주석이나 별도 메모로 남겨두고, 실제 수정은 별도 작업으로 분리한다.
- 코멘트나 피드백을 남길 때는 기존 내용을 바로 고치기보다, 작성자와 날짜를 표기한 추가 질문/의견 블록으로 남기는 방식을 선호한다.

## 절대 규칙 (2026-06-10 한경준 지시)

- **`raw/` 폴더는 절대 삭제 금지.** 어떤 정리·리팩토링·cleanup 작업에서도 `raw/` 내 파일 및 폴더를 삭제하거나 이동시키지 않는다. 읽기 전용 원본 소스 보관소이며, 삭제 요청이 명시적으로 있어도 재확인 후에만 진행한다.

## 프로젝트 성격

- `cnc-wiki`는 사내 CNC/MCT 가공·공구 연삭·재연마·출하/KPI 데이터를 모으는 지식 위키 겸 자동화 작업 공간이다.
- 핵심 흐름은 `raw/` 원본 자료 보존 → `wiki/` Markdown 정리 → `dist/` 웹 화면 생성 → Google Drive/Sheets 또는 배포 연동이다.
- `wiki/_handoff/`는 Claude, Cowork, Codex 사이의 컨텍스트 단절을 줄이기 위한 공유 기억 공간이다.

## 정보 분류 원칙 (2026-05-11 합의)

회사 차원의 공식 대외비 정책은 없으며, 통상 단가·금액만 민감 정보로 취급. 따라서 위키 데이터는 다음 기준으로 분류:

| 분류 | 항목 | 처리 방법 |
|---|---|---|
| **일반 데이터** | 사용 등급, 코팅 종류·비율, 입자 분포, 형상별 수명, 마모 패턴, 연삭 조건, 외주 업체명·납기, 운영 노하우 | 일반 wiki 페이지에 직접 입력 |
| **익명화 권장** | 거래처별 데이터, 특정 고객 가공 조건 | "거래처 A/B/C" 또는 "고객 X" 표기 |
| **진짜 대외비** | **단가·금액** (재연마, 재코팅, 신품, 거래처별), 마진 정보 | `wiki/_private/` 분리 또는 별도 시트 (미결정 시 항목명만 wiki에) |
| **개인정보** | 직원명·연락처·주민번호 등 (해당 시) | 절대 wiki에 두지 않음 |

> 다음 세션에서 "대외비"·"비공개"·"민감 정보" 언급 시 위 기준 우선 적용.
> 양식·페이지에 "대외비" 마커를 무분별하게 붙이지 말 것 — 단가가 아니면 일반 데이터.

## 메모 추가 규칙

- 반복해서 중요해지는 사실만 추가한다.
- 임시 아이디어나 단기 할 일은 `worklog.md`에 적고, 장기 원칙이 되면 이 파일로 옮긴다.
- 비밀값, 토큰, 비밀번호는 이 파일에 적지 않는다.
- 의견, 질문, 피드백은 원문을 덮어쓰기보다 아래 형식처럼 추가한다.

```markdown
> [작성자: Codex / 날짜: YYYY-MM-DD]
> 질문: ...
> 의견: ...
> 근거: ...
```
