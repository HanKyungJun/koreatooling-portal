## 2026-07-08: GITHUB_TOKEN push 403 근본 원인 확정 — fine-grained PAT Contents 권한 Read-only 상태였음
- 결정: 2026-07-07 발견된 push 403 오류의 근본 원인을 **fine-grained PAT의 Contents 권한이 Read-only로 설정(Read and write 아님)**되어 있었던 것으로 확정. 한경준님이 GitHub 토큰 편집 화면에서 Contents를 Read and write로 변경 후 저장(Update) 완료 → `git push --dry-run origin main` 재테스트로 성공 확인(`c680910..02c88d2 main -> main`).
- 근거: 스크린샷 실측 — 최초 화면은 "Repositories 0 / No repository permissions added yet"(권한 자체가 비어있음), 두 번째 화면은 Repository access에 3개 저장소는 선택돼 있으나 Contents 권한이 "Access: Read-only"로 표시(저장 전 편집 상태). 즉 **Repository access(저장소 선택)와 Permissions(권한 종류·수준)는 별개 설정**이며, 저장소만 선택하고 권한을 Read and write로 명시하지 않으면 push가 403으로 거부됨. git fetch/ls-remote(읽기)는 시종 정상 작동해 인증 자체는 문제없었고, 인가(authorization) 범위만 문제였음을 사전에 교차 확인.
