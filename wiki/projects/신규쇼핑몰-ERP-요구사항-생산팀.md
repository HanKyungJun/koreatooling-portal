# 신규 쇼핑몰 · ERP — 생산팀 요구 사항 (재연마)

> **이 문서의 역할**: 신규 쇼핑몰 · ERP 개발사에 생산팀이 「재연마 주문이 이렇게 돌아가야 한다」고 요구하는 목록. 요구마다 **이유(지금까지 실제로 겪은 일)** 와 **다 됐는지 확인하는 방법**을 붙였다.
> 규칙 · 기준: [[standards/재연마-견적-판정-명세]] · [[standards/재연마-입고검수-기준]] · 진행: [[projects/신규쇼핑몰-ERP-재연마-연동-준비]] 2-2 단계
> 우선순위: **필수** = 없으면 키오스크 주문이 돌지 않거나 인건비가 그대로 남음 · **권장** = 있으면 운영이 쉬움 · ⬜ = 회의에서 정할 것

---

## 1. 나누는 선 — 누가 무엇을

| 생산팀이 넘긴다 | 개발사가 만든다 |
|---|---|
| 재연마 판정 규칙(명세서) · 가격 데이터(`price_data.json` 또는 ERP 정가 기준 자료) · 검수 문항 세트 · 입고 검수 기준 · 마이다스 품번 ↔ 재연마 6항목 대응표(카탈로그 받은 뒤) | 쇼핑몰 화면 · 회원 · 결제 · 배송 · ERP 수주 연결 · 알림 |
| 정가표 개정 때 새 데이터 · 검수 문항 다시 만들기 | 새 데이터를 받아 바꿔 끼우는 기능(코드 수정 없이) |

## 2. 요구 사항

### 가. 가격 · 견적 화면

| ID | 요구 | 이유 | 확인 방법 | 우선 |
|---|---|---|---|---|
| R-01 | 재연마 금액은 판정 명세서 규칙 그대로 낸다 | 정가표는 블록이 흩어진 매트릭스라 잘못 읽으면 값이 2배 넘게 틀어짐([[standards/재연마-정가표-읽는법]] §0) | 검수 문항 세트(대표 49 · 구간 경계 4,256) 전부 같은 답 | 필수 |
| R-02 | 「OK」 일 때만 금액. 확인 필요 · 없음은 금액 없이 「담당자 확인」, 사유 문구에도 숫자 금지 | 2026-10-30 사내 프로젝트 시험에서 사유에 남은 ERP 옛 금액(43줄)이 답으로 나갈 뻔함 | 확인 필요 품목 화면에 숫자 0건 | 필수 |
| R-03 | 입력은 **선택 칸**(날수 · 형상 · 날경 · 재질 · 작업 부위 · 코팅)이 기본, 자유 문장은 보조 | 코팅 · 부위를 안 고르면 「코팅 확인」 줄이 생겨 사람이 다시 봐야 함. 선택 칸을 넣자 같은 줄이 OK 로 바뀜(2026-10-30 시험판) | 대표 문항 A ~ E 를 선택 칸으로 재현 | 필수 |
| R-04 | 마이다스 고객은 **품번을 고르면** 6항목이 자동으로 채워진다 | 자사 제품은 사양을 회사가 알고 있음 → 고객 입력 오류 · 「코팅 확인」 없음 | 마이다스 품번 표 전 품번 → 6항목 · 금액 일치 | 필수(마이다스 할인 시) |
| R-05 | 브랜드 할인(마이다스)은 **데이터로** — 할인율 · 반올림 단위가 바뀌어도 코드 수정 없음 | 할인 방식 미정(⬜) · 정가표도 연 2 ~ 3회 바뀜(26.05 · 26.09 · 26.10) | 할인율만 바꾼 데이터로 검수 문항 재실행 | 필수 |
| R-06 | 가격 데이터 교체만으로 갱신(코드 수정 · 재배포 없이) | 정가표 개정 때마다 개발사를 부르면 생산팀이 못 고침 | 새 데이터 파일 넣고 화면 반영 확인 | 필수 |
| R-07 | 금액 옆 「예상 금액 · 입고 검수 후 확정」 안내 | 실물 상태로 값이 바뀔 수 있음([[standards/재연마-입고검수-기준]] §5) | 화면 문구 | 필수 |
| R-08 | 직경 60 mm 넘는 「M이상」 칸도 값이 나와야 함 | 2026-10-30 검수 문항으로 웹 엔진이 「없음」으로 답하던 것 발견 · 정정 | 대표 문항 38(「2날 평 70 비코팅」) | 필수 |

### 나. 주문 · 접수

| ID | 요구 | 이유 | 확인 방법 | 우선 |
|---|---|---|---|---|
| R-11 | 주문이 들어오면 **ERP 수주가 자동으로 생성**(사람이 다시 입력하지 않음) | 인건비 절감의 핵심. 지금은 메일 · 시트를 보고 다시 입력 | 시험 주문 1건 → ERP 수주 · 품목코드 · 수량 · 거래처 확인 | 필수 |
| R-12 | 주문 줄 = ERP 품목코드. 없는 규격은 품목코드 생성 규칙대로 새로 만들거나 「확인 필요」 | 품목명 6칸 ↔ 품목코드 체계가 있고 직경 자리 3자리(0.1 mm) 한계가 있음([[standards/재연마-정가표-읽는법]] §1) | 미등록 규격 주문 시 처리 확인 | 필수 |
| R-13 | **서버 저장이 확인된 뒤에만** 「접수 완료」 + 주문번호 표시. 실패하면 실패 안내 · 입력 유지 | 지금 공개 폼은 전송이 실패해도 0.8 초 뒤 「접수되었습니다」를 띄움(2026-10-30 발견, 시험판 수정) | 네트워크 차단 상태 주문 → 실패 안내 | 필수 |
| R-14 | 자동 입력(스팸) 거르기 — 숨은 칸 + 건수 제한 | 공개 폼 주소는 누구나 보낼 수 있음(tasks 「공개 폼 GAS 스팸」) | 숨은 칸 채운 요청 → 저장 안 됨 | 권장 |
| R-15 | 개인정보는 필요한 것만 받고 처리방침 공개 | 개인정보보호법 제30조 처리방침 공개 의무 [IND-LAWTALK-PRIVACY-2022] — 법령 원문 · 전문가 확인 필요 | 수집 항목 목록 · 처리방침 페이지 | 필수 |
