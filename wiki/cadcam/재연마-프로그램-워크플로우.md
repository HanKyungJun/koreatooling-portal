# 재연마 프로그램 워크플로우 (CAD → CAM → 머신 → 검증)

> 마모·파손된 절삭공구를 재가공하기 위한 **프로그램 작성·시뮬레이션·머신 전송·실가공 검증** 전체 흐름. 본 위키 첫 CAD/CAM 페이지로, 다른 워크플로우 페이지의 모델 역할.
>
> 본 페이지는 [[anca-cnc-tool-grinder]] (장비) + [[연삭-조건-기록]] (조건 기록) + [[공구-수명-관리]] (수명 측정)을 **프로그램 측면**에서 연결합니다.
>
> ★★★ = 학술·표준 직접 근거 | ★★☆ = 산업 통례 + 매뉴얼 | ★☆☆ = 사내 추론

---

## 1. 워크플로우 개요 ★★☆

```
[입고 공구]
   │  ① 입고 검수·측정 (현물 데이터)
   ▼
[CAD — 공구 형상 정의]
   │  ② 도면 또는 현물 측정 기반 형상 입력
   ▼
[CAM — 프로그램 생성]
   │  ③ ANCA iGrind / ToolRoom RN 등
   │     - 표준 라이브러리 활용
   │     - 휠 스택 매칭
   │     - 절삭 조건 적용
   ▼
[시뮬레이션]
   │  ④ 가상 가공 — 충돌·간섭·결과 형상 확인
   ▼
[머신 통신·전송]
   │  ⑤ DNC / USB / 네트워크
   ▼
[실가공]
   │  ⑥ 첫 1개 가공 → 측정
   ▼
[검증·기록]
   │  ⑦ 합격 시 양산, 불합격 시 조건 재조정 ([[연삭-조건-기록]])
   └─ 데이터 누적 → [[공구-수명-관리]] §6
```

---

## 2. 단계 ① — 입고 검수·측정

### 2.1 검수 항목

| 항목 | 측정 방법 | 합부 기준 |
|---|---|---|
| 외관 결손 | 육안 + 광학현미경 | 기재 균열 없음 → 가능 |
| 직경 | 마이크로미터, 광학 측정기 | 사양 ± 한계 (사내 표준 §8 참조) |
| 길이 (전체·인선) | 캘리퍼·Z 게이지 | 잔여 인선 ≥ L_safe ([[공구-수명-관리]] §4.1) |
| 인선 마모 (VB) | 광학현미경 또는 비전 | VB ≤ 한계 또는 재연삭 가능 |
| 코팅 잔존 | 색상 + 측정 | 박리·소실 시 탈코팅 필요 |
| 형상 (코너 R 등) | 비전 또는 ToolMaster | 기준 형상에서 변형 정도 |

> 비전 시스템(Walter Helicheck, ZOLLER 등) 보유 시 자동 측정 가능. 미보유 시 수동 측정.

### 2.2 측정 데이터 → 다음 단계 입력

- 잔여 형상이 기준에서 얼마나 벗어났는지 → CAD 보정량
- 코팅 잔존 여부 → 탈코팅 필요 여부 → [[공구-코팅]] §7.1
- 인선 후퇴량 → 재연삭 횟수 카운트 ([[공구-수명-관리]] §4)

## 3. 단계 ② — CAD: 공구 형상 정의 ★★☆

### 3.1 입력 방법 3가지

| 방법 | 장점 | 단점 | 사용 시기 |
|---|---|---|---|
| **(a) 표준 라이브러리 호출** | 빠름, 검증된 형상 | 비표준 공구 불가 | 표준 엔드밀·드릴 |
| **(b) 도면 기반 직접 입력** | 정확 | 입력 시간 ↑ | 신규·특수 형상 |
| **(c) 현물 측정 → 역설계** | 도면 없어도 가능 | 측정 오차 누적 | 도면 분실 공구 |

### 3.2 핵심 파라미터 (엔드밀 예시)

| 파라미터 | 영향 | 표기 |
|---|---|---|
| 직경 (D) | 가공 폭, 휠 선택 | Ø__ |
| 날수 (Z) | 이송·표면조도 | 2/4/6날 등 |
| 코너 R | 측면 형상, 응력 분산 | R__ |
| 헬릭스 각 (θ_helix) | 칩 배출, 절삭력 | 30°/35°/45° |
| 라케 각 (γ) | 절삭 저항 | 양·음·중립 |
| 클리어런스 각 (α) | 마찰 감소 | 1차/2차 |
| 인선 길이 (LOC) | 가공 깊이 한계 | __mm |
| 전체 길이 (OAL) | 척킹·돌출 | __mm |

[출처: Trent & Wright 2000 Ch.5 / ANCA ToolRoom RN Manual]

## 4. 단계 ③ — CAM: 프로그램 생성 ★★☆

### 4.1 ANCA iGrind 워크플로우 (재연마용 표준)

ANCA iGrind는 ANCA 장비 표준 소프트웨어. 재연마용 핵심 기능:

```
1. 기존 프로그램 호출 (사내 라이브러리)
   또는 형상 신규 정의 (§3 입력)
2. 휠 스택 선택 ([[tools/wheels/index|wheels/]] / [[스택-1-1]] / [[스택-1-2]])
3. 절삭 조건 입력 (RPM, Feed, DOC) — [[연삭-조건-기록]] §3 표준 활용
4. 드레싱 주기·조건 설정 ([[연삭-이론-근거]] §7)
5. 사이클 모드 — 신품 신규 vs 재연마 (마모 형상 보정)
6. 프로그램 검증 (구문 체크)
7. NC 코드 생성·저장
```

### 4.2 ANCA ToolRoom RN (고급 — 신품 공구 설계)

ToolRoom은 ANCA의 고급 CAM. 주로 신품 공구 설계에 사용되나 재연마 보조에도 활용:
- 3D 모델링 + 시뮬레이션
- 표준 매크로 라이브러리 (Feedrate per element [RN34], feedrate optimisation [RN35])
- 커스텀 형상·복합 공구

[출처: ANCA ToolRoom RN 공식 매뉴얼 (사내 보유) / [[연삭-이론-근거]] §5]

### 4.3 기타 CAM 옵션 (비교 참고)

| 소프트웨어 | 제조사 | 강점 | 적용 |
|---|---|---|---|
| **iGrind / ToolRoom** | ANCA | ANCA 장비 표준, 강력한 라이브러리 | 본 위키 표준 |
| NUMROTOplus | NUM | 멀티 브랜드 지원 | 다양한 장비 |
| WALTER HELITRONIC | Walter | Walter 장비 통합 | Walter 사용 시 |
| HEINZ Mensch & Maschine | 다양 | 일반 CAM | 범용 |

> 본 위키는 ANCA 장비 기준이므로 **iGrind / ToolRoom 표준** 우선.

## 5. 단계 ④ — 시뮬레이션 ★★★

### 5.1 시뮬레이션 목적

1. **충돌 검증** — 휠-공구 간 의도치 않은 접촉
2. **간섭 검증** — 척킹·콜릿과 휠 충돌
3. **결과 형상 확인** — 의도한 코너 R, 헬릭스 각 등이 정확히 나오는지
4. **사이클 시간 추정** — 작업 부하 계획
5. **칩 배출 시뮬** (고급) — 깊은 가공 시 막힘 예측

### 5.2 시뮬레이션 한계

- ⚠️ 실제 열변형·진동·휠 마모는 시뮬에 반영 어려움 ([[연삭-이론-근거]] §6 냉각수 / §4 self-dressing)
- ⚠️ 시뮬 합격 ≠ 실가공 합격. 첫 1개 실가공 검증 필수.

[출처: Choi & Jerard 1998 / Smith & Tlusty 1991]

## 6. 단계 ⑤ — 머신 통신·전송 ★★☆

| 방법 | 속도 | 안정성 | 사용 시기 |
|---|---|---|---|
| **USB** | 중간 | 매체 분실 위험 | 단발성 전송 |
| **DNC (RS-232)** | 느림 | 안정적 | 레거시 머신 |
| **이더넷 네트워크** | 빠름 | 안정적 | 현대 머신 (권장) |
| **CF/PCMCIA 카드** | 중간 | 매체 노후화 | 일부 머신 |

> ⚠️ 보안: 머신이 회사 네트워크에 연결되어 있으면 멀웨어 위험. USB 사용 시 검사 권장.

## 7. 단계 ⑥⑦ — 실가공 + 검증 ★★☆

### 7.1 검증 가공 절차 (Run-Off)

```
1. 머신 워밍업 (30분~1시간) — [[anca-cnc-tool-grinder]]
2. 휠 드레싱 + 밸런싱 ([[연삭-이론-근거]] §4·§7)
3. 첫 1개 공구 — 절삭 조건 보수적 시작 (Feed 80% 등)
4. 가공 중 모니터링 — 부하·음향·열 (§7.2)
5. 가공 후 즉시 측정 — 직경·형상·표면조도·인선 라운딩
6. 합격 시 조건 100%로 양산
   불합격 시 [[연삭-조건-기록]] 폼으로 진단 → 조건 재조정
```

### 7.2 모니터링 항목

| 항목 | 정상 | 이상 신호 |
|---|---|---|
| 스핀들 부하 | 40~70% ([[연삭-조건-기록]] §4) | < 30% (로딩) 또는 > 80% (과부하) |
| 음향 | 일정한 절삭음 | 비명 (채터) 또는 비주기적 충격음 |
| 열 (휠/공구) | 손댈 수 있는 수준 | 표면 변색 (버닝, [[표면조도-불량]] §2.1) |
| 칩 색상 | 은회색 → 황금색 | 청·자색 (열 폭증) |

## 8. 사내 표준 워크플로우 (양식)

> [[memory|정보 분류 원칙]]에 따라 일반 데이터로 입력.

### 8.1 입고 → 출고 표준 사이클

> [2026-06-01 확인] 소요 시간은 형상별로 크게 다름. 기존 라이브러리 사용 시 단축, 신규 프로그래밍 시 증가.
> 장비: **F (Ø2~Ø8)** / **G (Ø10~Ø20)**

> [확인: 2026-06-05 한경준] 전체 사이클 소요 시간 **2~10분/개 (기존 프로그램 기준)**. 신뢰도: 사내 경험값.
> 형상·직경·복잡도에 따라 편차 큼. 소형(Ø2~Ø4) 단순형 최소 2분, 대형·복합형 최대 10분+.

| 단계 | 기존 프로그램 (분) | 신규 프로그래밍 (분) | 담당 | 도구 |
|---|---|---|---|---|
| 입고 검수 | 확인 필요 | 확인 필요 | 한경준 | 육안 |
| CAD/CAM 프로그래밍 | 단축 (라이브러리 호출) | 확인 필요 | 한경준 | ANCA ToolRoom |
| 시뮬레이션 | 확인 필요 | 확인 필요 | 한경준 | ANCA ToolRoom |
| 머신 셋업·전송 | 확인 필요 | 확인 필요 | 한경준 | ToolRoom → 장비 |
| 실가공 (1개당) | **2~10분** | **2~10분** | — | F 또는 G 장비 |
| 검수·기록 | 확인 필요 | 확인 필요 | 한경준 | 육안 |
| **합계 (1개 기준)** | **~2~10분** | 더 소요 | | 사내 경험값 |

### 8.2 사내 표준 라이브러리

> [확인: 2026-06-05 한경준] 표준 라이브러리 코드명은 공구 규격 기준에 따라 다름. ANCA ToolRoom에서 사용하는 .tom 파일이 사실상 라이브러리 역할. 별도 명명 규칙 미확립.
> `raw/tool/` 폴더의 .tom 파일 165개가 사내 라이브러리 원본 (서버 이동됨). `parse_anca.py`로 목록 추출 가능.

| 라이브러리 코드 | 장비 | 적용 공구 형상 | 직경 범위 | 비고 |
|---|---|---|---|---|
| .tom 파일명 기준 | F | 볼 엔드밀 | Ø2~Ø8 | 예: `2BA0601101.tom` |
| .tom 파일명 기준 | F | 코너R 엔드밀 | Ø2~Ø8 | 예: `4CO0601101.tom` |
| .tom 파일명 기준 | F | 평 엔드밀 | Ø2~Ø8 | 예: `4FL0601101.tom` |
| .tom 파일명 기준 | G | 볼 엔드밀 | Ø10~Ø20 | |
| .tom 파일명 기준 | G | 코너R 엔드밀 | Ø10~Ø20 | |
| .tom 파일명 기준 | G | 평 엔드밀 | Ø10~Ø20 | |
| .tom 파일명 기준 | F/G | 드릴 | — | |

> 사내 표준 코드 명명 규칙 미확립 → ANCA ToolRoom 파일명이 사실상 기준. 별도 체계화 원하면 decisions.md 등재 필요.

## 9. 자주 발생하는 문제 ★★☆

| 증상 | 1차 원인 후보 | 대응 |
|---|---|---|
| 시뮬 합격인데 실가공 불량 | 시뮬에 미반영된 열변형·진동 | 워밍업 강화, 보수적 첫 가공 |
| 결과 형상 ≠ 의도 형상 | CAD 입력 오류 또는 휠 드레싱 부정확 | 입력 재검토, 드레싱 ([[연삭-이론-근거]] §7) |
| 첫 가공 후 표면 불량 | 새 휠·새 조건 조합 미숙 | [[표면조도-불량]] §3 진단 트리 |
| 채터·진동 | 시스템 강성 부족 또는 회전수-고유진동수 일치 | [[표면조도-불량]] §2.3, 회전수 5~10% 변경 |
| 사이클 시간 과다 | Feed 보수적 과도 또는 비효율 경로 | iGrind feedrate optimisation (ToolRoom RN35) |
| DNC 통신 끊김 | 케이블 노후, 패리티 설정 오류 | 케이블 점검, 통신 파라미터 재설정 |
| 시뮬 충돌 경고 무시 → 실가공 사고 | 경고 검증 미흡 | 모든 충돌 경고는 원인 파악 후 해소 |
