# 사내 공유폴더 배포 실패 — SMB 자격증명 (192.168.0.252)

> 🔴 **암호는 이 문서에 기록하지 않는다.** 계정명까지만 남긴다 (CLAUDE.md §4 정보 분류 원칙).

**대상 경로**: `\\192.168.0.252\ToolKorea\생산팀\4.AI 자료실\현황판`
**영향 범위**: 사내 현황판(`dashboard.html` 외 20개 파일). 실패해도 파이프라인은 죽지 않고 **조용히 옛 화면이 남는다** — 이것이 이 증상의 핵심 위험이다.

---

## 1. 증상과 오류 코드 (★★★ — 실측 검증)

`generate.py` 의 `publish_internal()` 은 UNC 경로에 `os.makedirs()` 로 **바로** 접근한다. `net use`·`cmdkey` 호출이 없으므로 **호출자의 로그온 세션에 이미 확립된 SMB 자격증명에 전적으로 의존**한다.

| 오류 | Windows 의미 | 이 환경에서의 해석 |
|---|---|---|
| `WinError 1312` | `ERROR_NO_SUCH_LOGON_SESSION` — 로그온 세션 자체가 없다 | 예약 작업이 **S4U**(「암호를 저장하지 않음」)로 등록돼 저장된 자격증명을 쓸 수 없다 |
| `WinError 1326` | 자격증명 불일치 | 세션은 있으나 **계정명 또는 암호가 서버와 어긋났다** |
| 오류 없음 + 배포 성공 | — | 대화형(Interactive) 세션에서 실행됨 |

⚠️ **`LastTaskResult = 0` 으로는 판정할 수 없다** [실측 교차 대조 — 2026-09-09]. `publish_internal()` 이 예외를 밖으로 던지지 않는 설계(의도된 것)라, 사내 배포가 실패해도 예약 작업은 「성공」으로 끝난다. **반드시 로그의 `사내 배포 단계 종료` 줄을 봐야 한다.**

⚠️ **로그가 2개다 — 둘 다 봐야 한다.** `scripts/daily_and_upload.bat` 1단계의 `daily_report.py` 가 내부에서 부르는 generate.py 는 **`run.log`**, 마지막 단계의 generate.py 는 **`generate.log`** 에 쓴다. 한쪽만 보면 회차의 절반을 놓친다.

## 2. 진단 절차 (PowerShell — 한경준님 실행)

### 2-1. 배포 성패 확인 (로그)

```powershell
cd C:\Users\TOOLKOREA\Desktop\cnc-wiki\wiki\reports\daily
Select-String -Path run.log, generate.log -Pattern "사내 배포 단계 종료" | Select-Object -Last 6
```

### 2-2. 예약 작업 상태

```powershell
Get-ScheduledTask | Where-Object { $_.TaskName -match 'CNC|Daily|Report|generate' } |
  Select-Object TaskName, State, @{n='LogonType';e={$_.Principal.LogonType}}, @{n='UserId';e={$_.Principal.UserId}}
```

`LogonType = S4U` 이면 `1312` 의 구조적 원인이다.

### 2-3. 🟢 자격증명 시험 — **저장하지 않는 방법으로 먼저**

```powershell
net use \\192.168.0.252\ToolKorea /user:hzn20012 *
```

암호를 대화형으로 물어보고 **성패만 알려준다. 아무것도 저장하지 않으므로 되돌릴 필요가 없다.** 자격증명을 건드리기 전에 항상 이것부터 한다.

### 2-4. 🟢 클린세션 대조 — 재부팅을 기다리지 않는 법

```powershell
net use * /delete /y
```

열린 SMB 세션을 전부 끊으면 **재부팅과 동등한 조건**이 된다(「목록에 항목이 없습니다」 확인). 이후 실행은 매번 실제 인증을 거치므로 **당일에 판정할 수 있다.** 2026-09-15 에 이 방법으로 4일치 교착을 풀었다.

## 3. ⚠️ 해서는 안 되는 것

- 🔴 **`cmdkey /add ... /pass` 를 조건부 블록 안에 넣지 않는다.** 별도 턴으로 분리한다. 2026-09-15 에 「1326 이 나왔을 때만」 조건이 붙은 3단계가 조건 없이 실행돼 **작동하던 자격증명이 파괴**됐다.
- 🔴 **`cmdkey` 는 저장된 암호를 읽어 올 수 없다.** 따라서 「되돌릴 수 없는 조작 전에 현재 값을 먼저 읽어 기록한다」는 일반 규칙이 **암호에는 적용되지 않는다.** 덮어쓰면 원상복구가 원리적으로 불가능하고, 맞는 암호를 다시 입력해야만 복구된다(2026-09-15, **44분 소요**).
- 🔴 **성공 1회로 종결하지 않는다.** 2026-09-07 · 09-11 · 09-14 에 각각 조기 종결했다가 재발했다. 종결 판정은 **부팅·로그온을 거친 회차**에서 한다.

## 5. 🔴 미해결 — 복구 경로가 없다

2026-09-15 에 자격증명이 파괴됐을 때 복구 수단은 **한경준님이 암호를 기억하고 있었다는 것 하나뿐**이었다. 기억이 안 났다면 복구 경로가 없었고 사내 현황판은 계속 멈춰 있었을 것이다.

확인이 필요한 것:

1. 서버 `192.168.0.252` 의 **관리 주체**(부서·담당)
2. 계정 `hzn20012` 의 **암호 재설정 요청 경로**
3. **암호 만료 정책** 유무 — 있다면 만료일을 미리 알 수단

> 확인되면 이 절을 갱신하고 `tasks.md` 의 해당 P1 항목을 닫는다. **계정명까지만 기록한다.**

## 6. 🟢 실패를 알아차리는 장치 (2026-09-14 신설)

배포가 실패하면 공유폴더에 접근할 수 없으므로 **배너를 그 폴더에 쓸 수 없다** — 실패를 실패한 통로로 알릴 수는 없다. 그래서 배포 성공 여부에 의존하지 않는 두 경로를 뒀다.

| 겹 | 방식 | 배포 성공에 의존? |
|---|---|---|
| **A. 화면 자가 진단** | 현황판이 자기 `DASHBOARD_GENERATED_AT` 을 읽어 오늘이 아니면 빨간 띠를 띄운다 | ❌ — 옛 파일의 JS 가 스스로 판단 |
| **B. 메일 알림** | `publish_internal()` 실패 시 1통(성공→실패 전환 시, 하루 1통 제한). 상태는 `outputs/.internal_deploy_state.json` | ❌ |

A 가 근본 장치다. 배포가 며칠 멈춰도 **현장이 화면을 여는 순간** 옛 자료임을 알게 된다.
