# 재연마 견적 판정 명세 (쇼핑몰 · ERP 연동용)

> **이 문서의 역할**: 고객이 공구 사양을 고르거나 적으면 **재연마 정가가 얼마인지, 아니면 담당자 확인으로 넘길지**를 정하는 규칙을 한곳에 적는다. 쇼핑몰 · 새 ERP 를 누가 만들든 이 규칙과 §6 데이터 파일, [[projects/신규쇼핑몰-ERP-재연마-연동-준비|검수 문항 세트]]를 넘기면 같은 답을 내도록 만들 수 있다.
> **기준 구현**(이 규칙대로 동작하는 코드): `scripts/price_lookup.py`(Python) · `scripts/price_lookup_core.js`(웹) · `scripts/price_app/price_core.py`(사내 프로그램) · `scripts/quote_price.py`(여러 줄 견적). 세 엔진은 2026-10-29 대조 11,616 조합 · 문장 12개 같은 결과 [실측 검증].
> **정가표 칸을 어떻게 읽는지**는 [[standards/재연마-정가표-읽는법]]. 이 문서는 그 위의 **판정 규칙**만 다룬다.
> **금액은 적지 않는다** — 정가는 대외비가 아니지만(CLAUDE.md §4-1) 개정마다 바뀌므로 값은 데이터 파일에서만 읽는다.

## 1. 범위

| 포함 | 제외 |
|---|---|
| 재연마 **공표 정가**(할인 전, 개당) | 거래처별 할인율 · 실거래 단가(대외비) |
| 정가가 정해지는 사양 판정 · 「담당자 확인」으로 넘기는 조건 | 신품 판매 가격 |
| 여러 줄 견적의 소계 · 합계 규칙 | 결제 · 회원 · 배송(쇼핑몰 쪽 기능) |
| 브랜드 할인(마이다스) 확장 자리 — §8 | 할인율 값(미정) |

## 2. 입력 — 6항목

재연마 품목은 아래 6항목이 정해지면 값이 하나로 정해진다. ERP 품목명 「`2날/라핑평/12.5mm/HSS/밑날/일반 코팅`」(슬래시 6칸)이 같은 순서다.

| # | 항목 | 화면 선택지(권장) | 비고 |
|---|---|---|---|
| 1 | 날수 | 2날 · 3날 이상(1날 포함) | 정가표는 **2날과 그 외 두 행**만 있다. 3 · 4 · 6날 … 은 같은 값([[standards/재연마-정가표-읽는법]] §3) |
| 2 | 형상 | 평 · 볼 · 코너R · 라핑 평 · 라핑 볼 · 라핑 코너R · 리머 · 드릴 | 그 밖(챔퍼 · 테이퍼 · 스탭드릴 · 날붙이초경 등)은 정가표 블록 없음 → §3 ⑤ |
| 3 | 직경 D | 숫자(mm), 0.05 mm 단위로 판정 | 필수 |
| 4 | 재질 | 초경 · HSS | 입력 없으면 **초경**으로 보고 화면에 알린다 |
| 5 | 작업 부위 | 밑날(기본) · 밑날+옆날 · 옆날만 · 골수리 | 「밑골수리 · 밑외경 · 밑날+외경」 = 밑날+옆날. 입력 없으면 **밑날** |
| 6 | 코팅 | 비코팅 · 일반 코팅 · 고경도 코팅 | 입력 없으면 세 가지를 모두 보여 주고 견적 줄은 「코팅 확인」 |

- **필수는 형상 · 직경 두 가지**. 둘 중 하나라도 없으면 금액을 내지 않고 「형상(또는 직경)을 함께 입력」 안내만 한다.
- 자유 문장 입력(「10파이 2날 볼 고경도」)도 받는다. 해석 사전은 기준 구현의 `SHAPES · PARTS · COATS · MATS` 표(예: 하이스 = HSS, 무코팅 = 비코팅, 「코팅」만 있으면 일반 코팅). 쇼핑몰은 **선택 칸을 기본**으로 하고 자유 문장은 보조로 두는 것을 권한다 — 해석 오차가 없어진다.
- 입력 칸이 슬래시 6칸 표준 품목명이면 해석 없이 그대로 쓴다.

## 3. 판정 순서 — 한 품목

위에서부터 처음 맞는 줄에서 끝난다.

| 순서 | 조건 | 상태 | 금액 표시 |
|---|---|---|---|
| ① | 형상이 리머이고 코팅이 고경도 | **확인 필요** | 없음 — 정가표 리머 블록은 비코팅 · 코팅 두 칸뿐(decisions 2026-10-30 (3)) |
| ② | 같은 품목의 등록 정가가 사업장끼리 다름 | **확인 필요** | 없음 |
| ③ | 정가표 계산값과 ERP 등록 정가가 다름 | **확인 필요** | 없음(사내 화면만 정가표 값을 참고로) |
| ④ | 정가표 계산값이 있음 | **OK** | 정가표 값 |
| ⑤-가 | 정가표 계산값 없음 · 등록 정가 있음 · **드릴** | **확인 필요** | 없음 — 26.10 드릴 표 밖(초경 20 mm 초과 · 3 · 4날 · 밑날 외)은 ERP 에 옛 정가가 남아 있음(decisions 2026-10-30 (1) · (2)) |
| ⑤-나 | 정가표 계산값 없음 · 등록 정가 있음 · 그 밖 형상 | **OK** | ERP 등록 정가 |
| ⑥ | 둘 다 없음 | **없음** | 없음 — 「담당자 확인」 + 가까운 등록 규격(직경만) 안내 가능 |

**정가표 계산값**을 구하는 규칙

- 블록 = 재질 × 형상 × 작업 부위 × 코팅 × 날수(2날 / 그 외). 드릴은 **2날 · 밑날만** 정가표에 있다(초경 · HSS 따로, 고경도 열 포함)
- 직경 구간은 **「N이하」 = (앞 구간 상한, N]** — 경계값은 작은 쪽 구간에 들어간다. 마지막 칸이 「M이상」 이면 상한이 없다(Ø70 · Ø200 도 같은 값). 정가표 라벨 사이에 빈틈이 있으면(예 「30이하」 다음 「33이상」) 그 사이 직경은 계산값 없음 → ⑤ · ⑥
- 고객 화면에는 **OK 일 때만 금액**을 보이고, 나머지는 모두 「담당자 확인」으로 쓴다. 사유 문구에 금액을 넣지 않는다(옛 금액 노출 방지, 2026-10-30 프로젝트 시험에서 확인)

## 4. 여러 줄 견적

견적 한 건 = 줄(규격 · 수량) 여러 개. 줄마다 §3 을 적용하고 아래 상태 하나를 붙인다.

| 줄 상태 | 조건 | 소계 |
|---|---|---|
| OK | 값이 하나로 정해짐 | 정가 × 수량 |
| 코팅 확인 | 코팅(또는 날수)을 안 골라 후보가 여럿이고 **그중 OK 가 하나 이상** | 비움 — 후보와 범위만 |
| 확인 필요 | §3 ① ② ③ ⑤-가, 또는 후보가 여럿인데 **OK 가 하나도 없음**(코팅을 골라도 금액이 안 나옴 — 예 드릴 표 밖) | 비움 |
| 정보 부족 | 형상 · 직경을 못 읽음 | 비움 |
| 대상 아님 | 구분이 재연마가 아님 · 재질 SKD 등(정가표 없음) | 비움 |

- 합계 = OK 줄 소계의 합. OK 가 아닌 줄이 하나라도 있으면 「일부 합계」로 표시한다
- 규격과 수량 줄 수가 다르면 줄마다 「짝 확인」 표시

## 5. 고객 화면 문구 (현재 시험판 기준)

- 금액 옆: 「공표 정가 기준 예상 금액(할인 적용 전, 개당). 실제 금액은 입고 확인 후 안내」
- 확인 필요 · 없음: 「담당자 확인」 — 금액 · 사유의 숫자를 쓰지 않는다
- 공개 범위 · 최종 문구는 대표님 확인 사항(tasks 「재연마 정가 조회기」)

## 6. 데이터 파일 — `price_data.json`

정가표 · ERP 가 바뀌면 `python scripts\build_price_app.py`(또는 `build_price_widget.py`)가 다시 만든다. 쇼핑몰 · ERP 는 이 파일만 받으면 §3 을 그대로 재현할 수 있다.

| 키 | 내용 |
|---|---|
| `made` · `pricelist` · `sheet` · `master_src` | 만든 시각(KST) · 정가표 파일 · 시트 · ERP 원본 |
| `length_rule` | 전장 할증 — `long_gt` 100 · `exlong_gt` 150(초과) · 적용 작업 부위 · 배수(초경 / 초경 라핑 / HSS) |
| `step` · `dmax` | 직경 판정 단위(0.05 mm) · 구간표를 내보낸 끝(60 mm). 마지막 구간 상한이 `dmax` 면 「M이상」 칸 = 상한 없음 |
| `combos` | 「재질\|형상\|작업 부위\|코팅\|날수(2 또는 4)」 → `[[하한, 상한, 정가], …]`. 직경 d 가 `하한 − step < d ≤ 상한` 이면 그 정가 |
| `registered` | 품목 비교키(소문자 · 공백 제거 슬래시 6칸) → ERP 등록 정가 |
| `conflict` | 사업장끼리 정가가 다른 품목 키 목록(§3 ②) |
| `mismatch` | 정가표 계산 ≠ 등록 정가 품목 키 목록(§3 ③) |
| `extra_shapes` | 정가표 블록은 없고 ERP 에만 있는 형상 이름(해석용) |
| `note` | 「정가만 · 할인율/사업장 단가 없음」 |

- 2026-10-30 판: combos 279 · registered 7,471 · conflict 24 · mismatch 194 [실측]
- **할인율 · 거래처 단가는 이 파일에 넣지 않는다.** 로그인한 거래처에게만 보여 줄 값은 ERP 쪽에서 따로 처리

## 7. 갱신 절차와 담당

1. 정가표 개정(생산팀) → ERP 정가 등록(담당자) → `python scripts\price_erp_check.py`(정가표 ↔ ERP 대조)
2. `build_price_app.py` · `build_price_widget.py` · `export_price_project.py` 로 데이터 · 화면 · 사내 프로젝트 지식 다시 만들기
3. [[projects/신규쇼핑몰-ERP-재연마-연동-준비|검수 문항 세트]]를 다시 돌려 답이 바뀐 문항만 확인
4. 새 `price_data.json` 을 쇼핑몰 · 공유 폴더에 교체

## 8. 확장 예정 — 브랜드 할인(마이다스)

회사 방향(2026-10-30 한경준님 전달, 정식 회의 전): 신규 브랜드 「마이다스」 구매 고객은 재연마를 더 싸게, 고객이 직접 골라 주문. 아래는 **제안**이며 확정 아님.

| 항목 | 제안 |
|---|---|
| 가격 | 같은 6항목 판정 결과에 브랜드 규칙을 하나 더 얹는다 — `brand_rules: {"마이다스": {"방식": "정가 × (1 − 할인율)" 또는 "전용 가격표"}}`. 할인율 · 반올림 단위는 회사 결정 |
| 브랜드 확인 | ① 고객이 **마이다스 품번을 고르면** 6항목이 자동으로 채워지고 할인가 표시(사양을 회사가 알고 있으므로 「코팅 확인」 줄이 생기지 않음) ② 입고 검수에서 각인(브랜드 · 품번) 확인 — 다르면 일반가로 바꾼다는 문구를 주문 화면에 미리 둔다 |
| 필요 자료 | 마이다스 품번 ↔ 재연마 6항목 대응표(카탈로그 받은 뒤 생산팀 작성) |
| 확정가 | 화면 금액은 예상가. 입고 검수에서 바뀌는 조건(큰 치핑 · 재연마 불가 · 횟수 한도)은 생산팀 기준으로 정함 |

## 9. 미정 · 확인 필요

- 🔴 **전장(L) 할증이 엔진에 없음**: 외경 · 옆날 · 골수리 작업은 전장 **L > 100 mm = Long, L > 150 mm = Ex-Long** 할증, 배수는 정가표 블록 메모(초경 E/M 외경연삭 ×1.2 / ×1.5 · 초경 라핑 · HSS · HSS 라핑 · 날붙이 외경연삭 ×1.5 / ×2) — decisions 2026-10-30 (10). 지금 엔진 · 위젯 · 프로젝트 지식은 전장을 묻지 않아 **긴 공구의 옆날 작업을 낮게 답할 수 있다**. **화면 방식(decisions 2026-10-30 (11))**: 할증 안내 문구 + **버튼 두 개(「전장 100 mm 초과」 · 「전장 150 mm 초과」, 하나만 · 다시 누르면 해제), 안 누르면 100 mm 이하(기본), 필수 아님**. 고르면 할증 금액으로, 안 고르면 기본 금액 + 「전장 100 mm 초과 공구는 할증 — 입고 때 확인 후 다시 안내」. 입고 검수에서 실제 전장으로 확정. ✅ 엔진 반영(2026-10-30 오후 — `price_data.json` 의 `length_rule`, 검수 문항 L 10건, 엔진 3종 같은 답)
- 날장이 남지 않은 공구 = 제작(재연마 가격 아님), D1 이하 · 다이아 코팅 = 진행 안 함 — 화면에서 미리 걸러 낼지 검수에서 걸러 낼지

- 쇼핑몰 플랫폼(위젯을 넣을 수 있는지) · 새 ERP 의 품목 정가 기준 자료 · 주문 → ERP 수주 자동 생성 여부
- 마이다스 할인 방식 · 할인율 · 품번 목록
- 재연마 결제 시점(주문 때 / 검수 뒤)
- 고객 화면 공개 범위 · 문구(대표님 확인)
