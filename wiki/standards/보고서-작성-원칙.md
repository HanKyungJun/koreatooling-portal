## 0. 사내 규칙 — 맨 위 핵심 요약 3줄 (2026-10-21 확정)

> 근거: decisions.md 2026-10-21 · 원칙 출처 [SYS-BLUEHOUSE2005] §1 ③ 「결론 먼저」 · §6.2
> 기존 매뉴얼은 「결론 먼저」만 정하고 형식은 정하지 않았음 → 사내에서 형식을 3줄로 고정.

**모든 보고서는 제목 바로 아래에 핵심 요약 3줄을 둔다.**

| 줄 | 내용 | 쓰는 법 |
|----|------|--------|
| ① 결론 | 무엇이 어떻게 되었나 / 무엇을 하자는가 | 한 문장. 보고받는 사람이 이 줄만 읽어도 요지를 알게 |
| ② 근거 | 결론을 받치는 핵심 수치 1~2개 | 단위 필수(RPM · mm · m/s · Ra μm · 개/일 등) + 신뢰도(제조사 기준 / 실측 검증 / 사내 경험값 / 추정값) |
| ③ 요청 | 보고받는 사람이 결정 · 승인 · 확인할 것 | 없으면 「요청 없음(참고 보고)」이라고 적는다 |

- 문체: 1줄 = 1문장, 개조식 명사형(~함 · ~했음) — §3 과 같음
- 근거가 없어 못 채우는 줄은 지어내지 않고 **「확인 필요」** 로 둔다
- 적용 대상: 일일보고 · 회의결과 · 결과 보고(docx) · 대표님 보고 · 발표자료(pptx는 표지 다음 장에 3줄)
- 적용 제외: `_handoff/worklog.md` 핸드오프 블록 · decisions.md ADR(각자 고유 양식) · 자동 생성물(주간브리핑 등)은 생성 스크립트를 고칠 때 반영
- 소급 수정 안 함 — 2026-10-21 이후 새로 쓰는 보고서부터

**예시** (형식 예시 — 수치는 2026-10-20 넥 시험 기록에서 인용)

```
① 넥 진입 찍힘은 황삭 Diagonal + 정삭 Stock 0.020 mm 로 해소됨.
② 테스트 2: 찍힘 없음(현미경 확인, 실측 검증 · 공구 1개) / 황삭 이송 10 → 4 mm/min 에서 부하 5 % → 4 %.
③ 테스트 2 공구 재정삭 여부 판단 요청.
```

> 참고: 이 규칙을 정할 때 한경준님이 웹 보고서 프롬프트 템플릿(블로그 · 커뮤니티, 출처 우선순위 5순위 — 보조 참고)을 가져옴. 그 템플릿의 구조(현황 → 문제점·원인 → 대안 → 효과 → 요청) · 개조식 · 가명화는 이미 §2 · §3 · CLAUDE.md §4 에 있어 새로 넣지 않았다.

## 1. 내용 작성 3대 원칙

### ① 수요자(보고받는 사람) 관점에서 작성

- 전문용어·어려운 한자·불필요한 외래어 지양. 필요 시 괄호 주석 또는 참고자료 첨부
- 작성자의 이해관계·선입견 배제 — 과거 사례·타부서 의견까지 포괄 검토 후 작성
- 수요자가 필요로 하는 **시점**에 보고 (적시성)

### ② 보고서 자체로 완결성 확보

- 다른 자료 없이 그 보고서만으로 이해 가능해야 함
- 읽고 나서 **추가 질문이 발생하지 않도록** 명확히 서술
- **1보고서 1주제** — 여러 주제 혼합 금지
- 분량은 적을수록 좋음. 5매 초과 시 목차 + 하이퍼링크

### ③ 표준화된 양식으로 간결·명료하게

- 6하 원칙 기준. 미사여구·애매한 표현·과장 지양
- 시작 문단에 가장 중요한 내용 배치 (특히 상황·정보보고서는 **결론 먼저**)
- 단순 사실 나열이 아니라 **의사결정이 필요한 쟁점**을 적시

## 2. 표준 구조 — 제목·개요·본론·말미

| 구간 | 역할 |
|------|------|

| **개요** | 전체 요약 또는 작성 배경·목적·경위 |

| **말미** | 결론·대안 제시, 건의, 향후 조치. 필요 시 참고자료 첨부 |

## 3. 문장 표현 요령

- 개조식 기본이되 '한편·다만·특히' 등 접속어로 문맥 연결 (주어·목적어 과도 생략 주의 — 필요 시 서술식 병용)
- 능동형 표현, 단순한 문단 구조. 형용사·부사보다 **명사·동사** 중심
- **1문단 1초점**. 동일 단어·문구의 2중, 3중 반복 억제
- 결론·주장은 과장 없이 — 객관성·신뢰성 유지

### 5-A-2. 작성 규칙

1. **요약에는 새 정보를 넣지 않는다** — 2부에 있는 것만 줄여 쓴다. 약어는 처음 1회 풀어 쓴다 [STD-NISO-Z3918] §5.2.1
2. **사실 · 해석 · 추정을 섞지 않는다** — 측정값(실측 검증) / 해석(근거 측정값 명시) / 사진 판독 · 유추(추정값)
3. **판정은 기준 먼저** — 「허용 2.807 ~ 2.881 mm → 2.853 ✅」처럼 기준과 값을 같이 적는다
4. **실패 · 철회도 지우지 않는다** — 틀린 해석은 취소선 + 철회 사유로 남긴다(예: 2026-10-20 「1회 −0.05 mm」 → 비접촉 확정으로 철회)
5. **실측 vs 제조사 기준이 다르면 둘 다** 적고 차이 원인 · 실측 환경(장비 · 휠 · 쿨런트 · 소재)을 붙인다
6. **표본 수를 늘 적는다** — 공구 1개 결과는 「실측 검증(공구 1개)」. 공구 1개로 사내 경험값 · 기준값을 만들지 않는다
7. **양산 적용 여부를 머리 정보와 결론에 둘 다** 적는다(❌ 미적용 / 🔄 검증 중 / ✅ 적용)
8. ⚠️ 경고 대상(Vc > 30 m/s · CBN 고RPM · 초경 고절입 · MCT 고이송, 사내 상한 초과 RPM)은 결과 표 안에 `⚠️ 경고:` 로 표시
9. 거래처는 A / B / C, 단가 · 금액은 넣지 않는다(CLAUDE.md §4)
10. 형식: Word A4 맑은 고딕 제목 22pt · 본문 15pt · 표 13pt(§4 사내 기준)

- [ ] 입수 정보를 논리적으로 체계화했나 (불필요한 반복 제거)
- [ ] 제목이 전체 내용을 함축하나 / 구성이 압축·간결한가
- [ ] 짧은 문장인가 (2줄 내외) / 미사여구·전문용어 회피했나
- [ ] 자기 부서 시각만으로 평가하지 않았나 / 유관부서 의견을 왜곡 없이 반영했나

### 6.3 회의자료 / 회의결과

- [ ] (자료) 논의·결정이 필요한 사항 중심으로 구성했나, 처리 방향을 포함했나
- [ ] (자료) 한정된 시간에 논의 가능한 분량인가
- [ ] (결과) 중요한 회의결과를 반드시 정리·보고했나 — 논의 결과 중심, 중요도에 따라 상세/간략 조절
- [ ] (결과) 결정사항·담당·기한이 기록되었나
