## 0-B. 세션 종료 프로토콜 (필수)

세션 종료 전 `wiki/_handoff/worklog.md` **맨 위**에 핸드오프 블록을 추가합니다:

> 2026-11-03~: 블록은 **항목당 1 ~ 2줄, 전체 10줄 안팎**으로 짧게 쓴다. 긴 경위는 해당 위키 페이지 · tasks 항목에 두고 블록에는 경로만.

```markdown
## YYYY-MM-DD (#N) 핸드오프 — [Cowork|Code|챗]
- 한 일: ...
- 결과/산출물: ... (파일 경로 포함)
- 미완·블로커: ...
- 다음 단계 제안: ...
- 검토: R? 주 · R? — 통과 n · 확인 필요 n · 통과 뒤 지적 n
- 챗으로 가져갈 질문: ...
```

- 「검토:」 줄(2026-11-18~): 그 세션 산출물 검토 줄의 합계. 「통과 뒤 지적」 = 통과라고 낸 뒤 한경준님이 짚은 Claude 실수 건수. 작은 일만 한 세션은 `- 검토: 작은 일(G1)` — AI 역할 검토표 4주 측정 자료(decisions 2026-11-18 (2))

세션 종료 시 아래 PowerShell commit 명령도 함께 제공합니다 (한경준님이 직접 실행). **이번 세션에서 바꾼 파일만 경로로** add 한다(2026-11-16 개정 — decisions 2026-11-16 (6)):

```powershell
cd C:\Users\TOOLKOREA\Desktop\cnc-wiki
git add -- "wiki/_handoff/worklog.md" "바꾼/파일/경로.md"
git commit -m "[이번 세션 작업 요약 — Claude가 작성]"
git push
git log --oneline origin/main..HEAD
```

- 마지막 줄 출력이 비면 push 완료. 한글 메시지가 길면 `-m` 대신 `-F outputs\commit_msg_YYYYMMDD.txt`(UTF-8, BOM 없음).
- add 목록은 이번 세션에서 직접 만들거나 고친 파일만. device_bash 읽기 명령 `git --no-optional-locks -c core.quotepath=false diff --ignore-cr-at-eol --numstat` · `status --short --untracked-files=all` 로 대조하고, 세션 밖 변경은 빼고 알린다. 상세 절차는 cnc-handoff 스킬 「커밋 안내」.
- ~~`git add .`~~ (2026-11-16 까지) — 세션 밖 변경 · CRLF 노이즈가 같이 들어가 폐기.
- `git-commit.bat` 은 **수동 백업 버튼**(전체 `git add .`) — 바뀐 파일 목록을 보여 주고 Y 를 입력해야 커밋한다. 세션 끝 커밋에는 쓰지 않는다(decisions 2026-11-16 (7)).
- 거래처 실명 검사는 커밋 때 pre-commit 훅이 자동으로 한다(decisions 2026-11-16 (1)).

> ⚠️ **Cowork(device_bash)에서 git 쓰기(add · commit · push · mv, `--dry-run` 포함)는 하지 않는다** — 인덱스 락이 남는다. 읽기 명령만 `git --no-optional-locks` 로 쓴다. ~~Cowork bash에서 git 명령은 동작하지 않습니다~~(2026-11-16 정정 — 읽기는 동작함)
> 파일 편집은 Edit/Write 도구로, commit은 반드시 한경준님이 PowerShell에서 실행합니다.

## 8. 워크플로우

### 8-1. 신규 페이지 작성

1. `wiki/_handoff/context.md`·`decisions.md` 확인 → 방향 정합 확인
2. `wiki/_handoff/sources.md`에서 관련 출처 ID 수집 (없으면 먼저 등재)
3. 해당 카테고리 스키마(§6)에 맞춰 페이지 작성
4. `wiki/index.md` 해당 섹션에 등재
5. `wiki/log.md`에 `[신규]` 항목 추가
6. 세션 종료 시 `worklog.md` 핸드오프 블록 작성 (§0-B)

### 8-2. 기존 페이지 보강

1. 현재 파일 내용 확인 후 편집 (기존 출처 ID 유지)
2. 추가 내용에 새 출처 ID 병기
3. `updated` 날짜 갱신
4. `wiki/log.md`에 `[업데이트]` 항목 추가

### 8-3. sources.md 신규 출처 등재

1. 해당 섹션(0-A, 0-B, … 또는 1~8)에 ID·APA 형식으로 추가
2. 섹션 7 "내부 위키 페이지 맵"에 페이지 ↔ 출처 ID 매핑 추가
3. 프론트매터 `sources` 필드에 ID 추가

### 8-4. 검수 (Lint)

정기 확인 항목:
- 페이지 간 가공 조건 모순 (같은 소재+공구인데 다른 조건)
- 출처 없는 수치 (→ "추정값" 명시 또는 출처 추가)
- 고아 페이지 (인바운드 링크 없음)
- 빨간 링크 (언급만 되고 페이지 없음)
- 프론트매터 누락·불완전
- sources.md ID 미등재 인용

**검수 제외 대상** (위 항목을 적용하지 않음):
- `wiki/_handoff/` 전체(아카이브 폴더 포함) — 핸드오프 기록물
- `wiki/index.md`·`wiki/log.md`·`wiki/overview.md` — 진입점·이력 (단, 다른 페이지로 가는 링크의 출발점으로는 집계)
- **`wiki/reports/09_업무일정/주간브리핑/`** — 예약작업이 매주 자동 생성하는 기록물. 고아·index 미등재·프론트매터 `sources` 누락을 지적하지 않는다 (2026-09-23 결정, decisions.md)
- `log.md` 안의 옛 경로·빨간 링크 — 추가 전용 이력이라 수정하지 않는다

### 15-4. 핸드오프 · 메모리 역할과 상한 (2026-11-03 신설)

| 구분 | 맡는 것 | 상한 |
|---|---|---|
| 핸드오프 · 위키 | 정확도의 원본 — 수치 · 출처 · 결정 · 진행 상태 | 가볍게 시작(§0-A)에서 읽는 양 합계 3,000자 이하 |
| 프로젝트 메모(MEMORY.md 목록) | 빨리 꺼낼 것 — 잘 바뀌지 않는 규칙 · 함정 · 위키 경로 | 20줄 · 한 줄 150자 이하, 🔴 규칙을 맨 위 |

1. 수치 · 출처 · 결정은 핸드오프 · 위키에만 원본을 둔다. 프로젝트 메모에 숫자를 적을 때는 위키 경로를 같이 쓰고, 메모만 보고 인용하지 않는다.
2. §0-A 의 P0 · P1 판정은 우선순위 바로 뒤 쉼표로 한다 — `(P0,` · `(P1,`. 「(P1 → P3」처럼 내린 항목과 양식 예시 줄은 빠진다(2026-11-03 실측: 옛 방식 14줄 1,304자 → 8줄 675자, 가볍게 시작 합계 2,410 → 1,781자).
3. 목록이 넘치면 ✅ 종결 · ⏸ 보류 · 도구 연동 항목부터 **목록에서 줄만 뺀다**. 내용 파일은 메모 폴더에 그대로 두고, 목록 맨 끝에 「목록 밖 보관 파일은 `project_memory_read` 로 확인」 한 줄을 남긴다. 🔴 `wiki/_handoff/memory.md` 등 공개 저장소로 옮기지 않는다(보안 절차 · 거래처명이 섞여 있음). 줄을 빼는 것도 §15-1 「이동」으로 보고 목록을 먼저 보여 준다.
4. 점검: 금요일 「주간 정리 제안」이 목록 줄 수를 잰다(못 재면 「확인 필요」). 세션 시작 때 목록에 잘림 표시(`[truncated]`)가 보이면 그 세션에서 바로 알린다.
5. 범위: cnc-wiki 프로젝트 메모에만 적용한다. 한경준님 계정 메모리(선호 · 프로필)는 Claude 가 따로 관리한다.

- 근거: 2026-11-03 실측 — 프로젝트 메모 목록 39줄 중 22줄만 세션에 보임(줄 중간에서 끊김 → 글자 수 기준, 상한 약 4,000자 추정값). 잘린 쪽에 git 읽기 전용 · KST · ERP 직접 조회 불가 등 🔴 규칙. decisions 2026-11-03 (3)
